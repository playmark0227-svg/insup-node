# INSUP NODE

管理者（PC）とプレイヤー（PC・スマートフォン）の成果・ランキングアプリです。GitHub Pagesで画面を配信し、Google Apps Scriptが非公開スプレッドシートの読み書きと本人確認を行います。

公開画面: https://playmark0227-svg.github.io/insup-node/

## 接続状態と設定

2026-10-08に実Googleの独立した検証用コピーでログイン・保存・再取得・数式保護・後始末を確認し、新しい管理用シートを保存先として有効にしました。所有者がWebアプリを公開し、GitHub Pages画面からPOSTによる接続確認も成功しています。`public/connection.json` に公開された接続URLを設定済みです。公開画面での管理者ログインと、同日11:41:45（JST）の認証付き実績再取得、取得時刻の更新を確認済みです。

確認途中にはGoogle応答の404・応答不明が発生し、その後の再取得で回復しました。Googleの一時結果URLで404が返った場合は、3秒後に結果だけを1回再取得します。保存処理は自動再送しません。Google側の応答が戻らない場合はエラーを表示し、入力内容と保存操作IDを保持します。

[Google側の設定手順](google-apps-script/SETUP.md)に沿って、所有者が作成した新しい管理用スプレッドシートへ元データを移し、Apps Scriptを設定します。今後の読み書きは新しい管理用ファイルで行います。元の原本への書き込みは、初期設定・管理タブ追加・行メタデータを含めて常に拒否します。

配布マニフェストにはGoogle Sheets API v4を含めています。Apps Scriptの「サービス」で設定を確認して保存した後、管理用スプレッドシートを再読み込みし、「NODE連携 → 新しい管理シートの初期設定」から開始します。初期設定や検証はシートのメニューから実行してください。既定のCloudプロジェクトではサービス追加でAPIも有効になり、Cloud Consoleでの手動操作は不要です。

移行は所有者が承認したブック全体のネイティブコピーで行いました。コピー作成と代表範囲の照合は済んでいます。コメントは原本に残り、コピーには含まれていません。外部参照の接続は未完了です。タブ単位の補助 `google-apps-script/Migrate.gs` は停止したまま使いません。[移行の状態と保全範囲](google-apps-script/MIGRATION.md)を確認してください。移行先IDや業務データは公開ソースへ埋め込みません。連携設定では元のタブ名と入力19列を検査し、移行先の実際のgidを登録します。初期設定と保存先の有効化は、移した業務セルの値・数式・書式を変更しません。

発行した `/exec` URLを画面の「データ連携」に入力してください。配布時の既定URLは `public/connection.json` に設定して再ビルドします。URLは公開設定情報であり、秘密鍵・パスワードは含めません。管理者には認証後の応答から接続中の保存先リンクを表示し、プレイヤーと未ログインの利用者へ保存先ファイル情報を返しません。

接続後はID＋パスワードでログインし、管理者は全体の明細、プレイヤーは本人の明細と全員のランキングを確認します。実接続の失敗をサンプルの実績へ置き換えません。セッションはタブ内のsessionStorageへ保存し、候補者・会社の業務データやパスワードを永続保存しません。

## 保存と集計

- 成果入力では「面談実施・提案数・C面談予約・C面談実施・マッチ数・稼働開始」の6項目を選択できます。候補者ごとに工程と実施日を登録し、提案以降は対象のクライアントへの提案行を選びます。内定や稼働開始予定も別工程として残します。
- 管理者ホームは成果ミーティング用です。6項目のチーム合計と全員比較、月間の前月差・提案目標達成率、個人ごとの発表表示と会議用拡大表示に対応します。評価のための合成点は作らず、登録された実績を表示します。
- 活動の登録、進捗の変更、プロフィール・目標の変更、管理者のID発行と担当名設定に対応します。
- アプリの保存処理は新しい管理シートの入力19列のみを更新し、KPI・非表示列・数式セルを上書きしません。見出し変更や行の競合は保存を拒否します。
- 保存・再取得したデータから成果とランキングを更新します。面談は同日・同担当・同候補者で重複除外、提案以降は提案行単位です。
- 成果登録は「2期目マッチングDB」に保存し、「2期目月間KPI・KGI」の数式で集計します。マッチはV列の承諾日、C面談実施はQ列、実際の稼働開始はX列の日付です。2026-10-08のKPI参照・担当名の調整は検証済みです（[調整記録](google-apps-script/MIGRATION.md)）。
- 「現在のステータス」の変更はG列だけを更新します。KPIに実績を反映するには、活動登録から工程と日付を記録してください。
- 応答不明の保存は同じ内容・操作IDで再試行し、二重保存を防ぎます。
- 初期設定は読み取り接続です。別の検証用コピーでログイン・保存・読み戻し・数式保護を実検証して署名証明を保存し、所有者が登録済みの新しい管理シートを有効化します。原本と新しい管理シートにテスト用の業務行は作成しません。

同じ担当に同姓同名の別候補者がいる場合は区別できません。運用前に担当名の対応、既存の数式範囲、直接編集との運用を確認してください。

2026-10-08の確認時点で、管理マスタの担当名と対応しない41行はアプリの明細・集計から除外されています。担当者の対応は未確定のため、既存の担当列や管理マスタを推測で変更せず、所有者による確認が必要です。

## 開発と公開

Node.js 22.13以上で `npm ci`、`npm run dev` を実行します。`npm test` はApps Script／SheetsのモックとAPIクライアントを検証します。`npm run build` は型チェックを行い、画面とGoogle側の設定ファイルを `docs/` に生成します。

GitHub Pagesは `main` ブランチの `/docs` を公開元に設定します。ソース変更後はビルドした `docs/` とソースを一緒にコミット・pushします。Apps Scriptの更新はGoogle側のデプロイも更新してください。

Viteのbaseは `/insup-node/` です。透過ロゴもこのサブパスから読み込みます。元のSites版は変更していません。
