# INSUP NODE

管理者（PC）とプレイヤー（PC・スマートフォン）の成果・ランキングアプリです。GitHub Pagesで画面を配信し、Google Apps Scriptが非公開スプレッドシートの読み書きと本人確認を行います。

公開画面: https://insupnode.vifight.com/

## 接続状態と設定

2026-10-08に実Googleの独立した検証用コピーでログイン・保存・再取得・数式保護・後始末を確認し、新しい管理用シートを保存先として有効にしました。所有者がWebアプリを公開し、GitHub Pages画面からPOSTによる接続確認も成功しています。`public/connection.json` に公開された接続URLを設定済みです。公開画面での管理者ログインと、同日11:41:45（JST）の認証付き実績再取得、取得時刻の更新を確認済みです。

確認途中にはGoogle応答の404・応答不明が発生し、その後の再取得で回復しました。Googleの一時結果URLで404が返った場合は、3秒後に結果だけを1回再取得します。保存処理は自動再送しません。Google側の応答が戻らない場合はエラーを表示し、入力内容と保存操作IDを保持します。

[Google側の設定手順](google-apps-script/SETUP.md)に沿って、所有者が作成した新しい管理用スプレッドシートへ元データを移し、Apps Scriptを設定します。今後の読み書きは新しい管理用ファイルで行います。元の原本への書き込みは、初期設定・管理タブ追加・行メタデータを含めて常に拒否します。

配布マニフェストにはGoogle Sheets API v4を含めています。Apps Scriptの「サービス」で設定を確認して保存した後、管理用スプレッドシートを再読み込みし、「NODE連携 → 新しい管理シートの初期設定」から開始します。初期設定や検証はシートのメニューから実行してください。既定のCloudプロジェクトではサービス追加でAPIも有効になり、Cloud Consoleでの手動操作は不要です。

移行は所有者が承認したブック全体のネイティブコピーで行いました。コピー作成と代表範囲の照合は済んでいます。コメントは原本に残り、コピーには含まれていません。外部参照の接続は未完了です。タブ単位の補助 `google-apps-script/Migrate.gs` は停止したまま使いません。[移行の状態と保全範囲](google-apps-script/MIGRATION.md)を確認してください。移行先IDや業務データは公開ソースへ埋め込みません。連携設定では元のタブ名と入力19列を検査し、移行先の実際のgidを登録します。初期設定と保存先の有効化は、移した業務セルの値・数式・書式を変更しません。

発行した `/exec` URLを画面の「データ連携」に入力してください。配布時の既定URLは `public/connection.json` に設定して再ビルドします。URLは公開設定情報であり、秘密鍵・パスワードは含めません。管理者には認証後の応答から接続中の保存先リンクを表示し、プレイヤーと未ログインの利用者へ保存先ファイル情報を返しません。

接続後はID＋パスワードでログインし、管理者は全体の明細、プレイヤーは本人の明細と全員のランキングを確認します。実接続の失敗をサンプルの実績へ置き換えません。セッションはタブ内のsessionStorageへ保存し、候補者・会社の業務データやパスワードを永続保存しません。

## 保存と集計

- 成果入力では「面談実施・提案数・C面談予約・C面談実施・マッチ数・稼働開始」の6項目を選択できます。候補者ごとに工程と実施日を登録し、提案以降は対象のクライアントへの提案行を選びます。内定や稼働開始予定も別工程として残します。
- 管理者ホームは成果ミーティング用です。6項目のチーム合計と全員比較、月間の前月差・提案目標達成率、個人ごとの発表表示と会議用拡大表示に対応します。評価のための合成点は作らず、登録された実績を表示します。
- 活動の登録、進捗の変更、プロフィール・目標の変更、管理者のID発行と担当名設定に対応します。
- アプリの保存処理は新しい管理シートの入力19列のみを更新し、KPI・非表示列・数式セルを上書きしません。見出し変更や行の競合は保存を拒否します。
- 保存・再取得したデータから成果とランキングを更新します。面談は同日・同担当・同候補者で重複除外、提案以降は提案行単位です。
- 成果登録は「2期目マッチングDB」に保存し、「2期目月間KPI・KGI」の数式で集計します。マッチはV列の承諾日、C面談実施はQ列、実際の稼働開始はX列の日付です。2026-10-08のKPI参照・担当名の調整は検証済みです（[調整記録](google-apps-script/MIGRATION.md)）。
- 「現在のステータス」の変更はG列だけを更新します。KPIに実績を反映するには、活動登録から工程と日付を記録してください。
- 応答不明の保存は同じ内容・操作IDで再試行し、二重保存を防ぎます。
- 初期設定は読み取り接続です。別の検証用コピーでログイン・保存・読み戻し・数式保護を実検証して署名証明を保存し、所有者が登録済みの新しい管理シートを有効化します。原本と新しい管理シートにテスト用の業務行は作成しません。

同じ担当に同姓同名の別候補者がいる場合は区別できません。運用前に担当名の対応、既存の数式範囲、直接編集との運用を確認してください。

2026-10-08の確認時点で、管理マスタの担当名と対応しない41行はアプリの明細・集計から除外されています。担当者の対応は未確定のため、既存の担当列や管理マスタを推測で変更せず、所有者による確認が必要です。

## 開発と公開

Node.js 22.13以上で `npm ci`、`npm run dev` を実行します。`npm test` はApps Script／SheetsのモックとAPIクライアントを検証します。`npm run build` は型チェックを行い、画面とGoogle側の設定ファイルを `docs/` に生成します。

GitHub Pagesは `main` ブランチの `/docs` を公開元に設定します。ソース変更後はビルドした `docs/` とソースを一緒にコミット・pushします。Apps Scriptの更新はGoogle側のデプロイも更新してください。

Viteのbaseは `/insup-node/` です。透過ロゴもこのサブパスから読み込みます。元のSites版は変更していません。

## 端末への即保存とスプレッドシート同期

候補者の修正・新規登録、成果登録・取り消し、進捗、プロフィール、管理表、面談の振り返りは、端末のIndexedDBへの保存トランザクションが完了してからフォームを閉じます。入力はアカウントと接続先ごとに分離し、AES-GCMとエクスポート不可の端末鍵で暗号化します。パスワード・セッショントークンは保存キューに含めません。右上には「端末に保存済み・同期中」を表示し、Googleの確認前にシート反映済みと表示しません。

Googleへの書き込みは順番に行い、別の候補者・項目の入力は最大20件まで続けて受け付けます。同じ候補者・共有プロフィール・管理表の同じ行への重複編集は同期後まで止め、古い行バージョンを自動で置き換えません。同期中はログアウトを止めますが、アプリ内の画面移動は可能です。再読み込みやブラウザ再起動後も、同じ端末・アカウントで未同期入力を復元します。前回送信した可能性がある入力は勝手に再送せず、同じ操作IDでの再確認を案内します。ブラウザを閉じている間は同期しません。端末のブラウザデータを消すと未同期入力も消えるため、シート反映前の端末保存と共有先への保存は区別します。

Apps Script v11では、書き込み済みの応答を`responseMode: receipt`で返し、重い全件集計は別リクエストに分けます。既存行の数式・空欄の確認は行単位にまとめています。原本保護・行バージョン・権限・原子的な保存履歴・同じIDでの再試行は維持します。旧バージョンからのスナップショット応答にも対応します。

架空データと10秒の疑似通信遅延を使い、アプリ本体の候補者フォームと実ブラウザの暗号化端末保存を検証しました。受付は初回17.8ms、続けて5.7msで完了し、フォーム終了・連続受付・再読み込み後の復元・同じIDでの再確認を確認しました。480件の自動テスト、ビルド、公開物・依存関係のセキュリティチェックを通過。実際の業務シートへのテスト書き込みは行っていません。0.5秒は端末保存を含む操作完了の目標で、Googleへの実反映時間の保証ではありません。

保存エラーが確定した候補者・進捗・成果などは、右上の保存状況から「内容を修正して再保存」を開き、保持した入力をその場で直せます。未来の実施日は該当欄に表示し、予定日は未来も許可します。修正は暗号化した端末内データを一つのトランザクションで置き換えてから、新しい操作IDで再同期します。端末保存が失敗した場合は元の入力を保持します。通信結果が不明な保存は編集せず、同じ操作IDで確認します。ID・権限・行の版番号は修正欄から変更できません。

成果登録・候補者の追加／編集・基本情報は、右から開く入力パネルに統一しています。外枠は幅:高さ＝4:5に固定し、画面に収まるよう同比率で縮小します。項目数や工程の変更では外枠を変えず、入力欄のみ縦スクロールします。見出し・保存ボタンは固定表示し、背景の一覧は幅を縮めません。

## 月別の自動更新

画面は日本時間の毎月1日0時に当月へ切り替わります。開いたままの日付変更や、休止していたタブの復帰にも対応します。「今月を自動表示」に切替設定を表示し、過去月を手動選択した場合は固定表示します。「今月に戻る」で自動切替を再開できます。サイドバーとプロフィールの「今月」は常に現在月です。

各工程の実績は、その工程の日付から月別に集計します。翌月の実績がなければ0件で始まり、累計・過去月・進行中の候補者を保持します。新しい月のために行をコピー・削除・初期化する必要はありません。目標は現在のプレイヤー設定を毎月利用し、月別の目標履歴は管理していません。既存KPIシートの月見出し・数式範囲を自動延長する変更ではありません。

AIの月別集計範囲も選択月に追従します。日付が変わった際は保存済み結果・利用残回数を読み直し、AI生成を自動実行しません。入力中の下書き・保存待ちの内容は月初にも書き換えません。

架空の日時で10月31日から11月1日への画面切替、過去月の実績表示、自動表示への復帰、フォームの下書き保持、PC・スマホ幅を確認。年月境界・閏年・タブ復帰、実際のApps Scriptによる月別／累計／重複除外のテストを追加。実シートへの書き込みやApps Scriptの更新はしていません。

## 候補者・提案の削除と復元

「成果・活動記録」の各行から削除を開き、この提案だけ、または同じ担当者の同名の登録をまとめて削除できます。同姓同名の別人が含まれ得るため、まとめて削除する場合は確認画面の会社、進捗、登録済み実績を確認します。保存が確定すると、その行と実績が一覧・ランキング・月別集計から外れます。「削除済み」から元に戻すと元の行と実績が復元します。削除・復元中も画面移動ができ、右上で保存結果を確認できます。

Google側では行を削除・移動せず、入力値を空にして復元用の変更履歴と行メタデータを保持します。数式、入力規則、書式、他の候補者の行は維持します。氏名・担当・実績日付が数式の行は安全のため削除を拒否します。削除済みの行にSheetsから直接変更が入った場合、上書きを防ぐため復元を拒否します。この機能にはApps Scriptと公開画面の両方の更新が必要です。

## 2026-10-19の紹介ミーティングを反映

録画の全4,563秒を1秒ごとに抽出し、ローカルOCRと重要場面の目視で入力項目・操作・元シートの色を確認しました。録画の細かな文字やURLは読み取りに限界があり、列番号の判断には実際の新しい管理シートの見出しを使用しています。

- 初回面談の基本情報、稼働条件、職歴、実績、PC・CRM・チャット経験を入力し、面談実績と一度に保存できます。「その他・補足」には項目名のないメモも保存できます。
- 紹介文は入力中に端末内の下書きを自動作成し、編集後は上書きしません。対応するPC Chromeでは、端末内のGemini Nanoが入力情報を読んで紹介文や個別の面談準備案を生成します。別のプレビューから確認して採用し、編集・コピー・保存・再表示できます。
- 取引先を登録・編集・候補から非表示にできます。過去の提案先名は書き換えません。
- クライアントの合格を候補者の承諾（マッチ）と区別して登録します。現行管理シートでは合格がU列、マッチがV列です。
- ヨミは任意で空欄から開始。候補者は面談日が新しい順に表示し、検索・並び順・行の間隔を切り替えられます。行の間隔の設定だけを端末に保存します。

基本情報は `_NODE_candidate_profiles`、取引先は `_NODE_clients` に保存します。これらは初回保存時に作成するアプリ管理用タブで、既存のA:ZやKPIの列を変更しません。基本情報は固定UUIDを提案行に紐付け、同名候補者を自動で統合しません。新しい提案に引き継ぐときは対象の基本情報を明示して選びます。閲覧は担当者本人と管理者に限ります。

既存の初回面談資料は、氏名・実際の面談日・担当者を照合した18名分を、32件の提案行へ紐づけて移行しました。項目名のない21・22行目の補足も行番号付きで保存しています。原本と既存の成果日付・KPIは変更していません。残る69名は氏名・日付・現在の2期目データとの対応が確定しないため、自動では紐づけず元シートに保持しています。

## 面談ごとのAI支援

「基本情報」のAIパネルで、紹介文と面談準備・振り返りを切り替えます。端末AIは対応するPC ChromeのPrompt APIを使用し、候補者の原文を端末内で処理します。初回はブラウザのモデル準備が必要です。スマートフォンや非対応端末では、Google無料APIが汎用の見出し・導入句・質問例を生成する「AI文章構成」を利用します。人物ごとの文章はクラウドAIへ送らず、原文との結合と質問の選択をブラウザ内で行います。この方式は個別原文のAI要約ではありません。

面談メモ、自分の振り返り、確認して採用した準備案は基本情報と一緒に保存します。採用しない生成結果と参考紹介文は保存せず、画面を閉じると破棄します。元の職歴や補足は省略せず保持します。勤怠の確認事項・元資料の補足・社内メモは共有文へ自動挿入しません。

管理者は「次の対応・AI支援」の「紹介文の共通ルール」で口調、長さ、項目順、紹介概要の有無を設定できます。選定済みの参考文を端末AIで読み、固定の書式設定だけを取り出して確認後に共有できます。明示された見出しの順序は端末内で確認して優先し、AIの案を編集欄に反映してから手動で保存します。参考文の本文や候補者情報を共有設定、外部API、ブラウザの永続保存へ含めません。適切でない投稿やSlack履歴の無選別な収集は行いません。

無料APIの文章構成は一人3回/日・チーム10回/日の既存枠を他のAI機能と共有します。同じ共通書式の保存済み構成は全員で再利用できます。端末内AIにはこのクラウド生成枠を使いません。採否や人物の能力を自動評価する機能はありません。

参照: [Chrome Prompt API](https://developer.chrome.com/docs/ai/prompt-api)、[Gemini API利用規約](https://ai.google.dev/gemini-api/terms)。
