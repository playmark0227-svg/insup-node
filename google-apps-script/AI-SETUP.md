# C面談の振り返り・Gemini無料枠

## 専用プロジェクト

Google AI Studioに `INSUP NODE Reviews Free`（`gen-lang-client-0637056241`）を作成済み。
課金は設定しない。プロジェクト一覧の請求階層が「無料枠」であることを確認する。
APIキーは所有者が作成し、Apps Scriptの「プロジェクトの設定 → スクリプト プロパティ」に保存する。
キーはチャット・スプレッドシート・公開リポジトリ・connection.jsonへ記載しない。

| プロパティ | 値 |
| --- | --- |
| NODE_GEMINI_API_KEY | 専用プロジェクトのAPIキー |
| NODE_GEMINI_FREE_TIER_CONFIRMED | true（課金未設定・無料枠を確認後） |

`gemini-2.5-flash-lite` の標準generateContentのみを利用。別モデルや有料処理への自動切り替えはない。
課金を後から有効化するとAPIの利用条件が変わる。アプリはGoogleの請求設定を検出する権限を持たないため、専用プロジェクトに請求アカウントを接続しない。
1日全体10回・1アカウント3回のアプリ上限を設け、同じ期間・同じ集計結果は6時間再利用する。Google側の無料枠・レート制限が優先され、429時は停止する。
API失敗も利用回数に数える。日本時間の日付が変わるとリセット。

## 保存・閲覧

新しい管理用スプレッドシートの `_NODE_interview_reviews` に、提案行ID・担当ID・C面談日・分類・詳細メモ・次回対応・更新版・更新日時を保存する。
初回保存でこのタブを追加する。既存のマッチングDBの列・数式・KPIは変更しない。C面談実施の記録を減らす機能ではない。
担当者は本人の提案だけ閲覧・更新。管理者は全体を閲覧・更新。
実施日変更時は最新の日付で集計し、マッチ・稼働開始済みの提案は集計から除外する。保存履歴は `_NODE_operations` で操作IDにより重複を防ぐ。
AIに送るのは固定された理由分類と件数だけ。氏名、会社、担当ID、日付、詳細メモ、次回対応は送らない。
Gemini無料枠は送信内容をサービス改善に利用するため、詳細メモの要約ではなく、分類集計からの改善提案として表示する。

## 有効化・公開前の確認

1. 専用キーの作成・保存は所有者が実施。
2. 新しいCode.gsを既存Apps Scriptに保存。
3. 既存の管理機能を含むため、独立した検証コピーで `verifyNodeManagementCopy` と `verifyNodeManagementCopyRemaining` を実行し、KPI整合性を確認する。
4. 検証コピーで振り返りの新規保存・更新・重複再試行、本人/他者の権限、マッチ後の集計除外を確認。
5. 氏名のない分類集計のみでGeminiの実応答を確認。
6. 本番データに架空の成果・理由を追加せず、ウェブアプリを新バージョンに更新。フロントを公開し、PC/スマホで再取得を確認。

ローカルのテスト合格は本番での保存やGoogle API接続の証明にはならない。
