## 紹介文とAIの確認境界

紹介文は同じ確認済み事実から社内版と企業向け版を組み立て、企業別の宛先・提示単価・税区分だけを設定で変更します。会社ごとの職歴・期間・業務・実績・具体的な工夫に安定したIDを持たせ、数字や会社をAIに自由に作り直させません。

端末内AIが整理するのは、根拠を関連付けた業務内容・具体的な工夫の文章です。本人の氏名、条件、単価、社内メモや、別会社の数字を新しい文章の補完材料にしません。不適切な書き換えがあった場合は、その部分の原文を残します。文字数の目安を満たすための経歴・成果の水増しはしません。

端末・ブラウザが端末内AIに対応していない場合や、モデル準備・生成が失敗した場合は、規定書式による整形と不足質問へ切り替え、AIによる生成を行っていないことを表示します。対応するPC版Chromeであっても、モデルの利用可能状態や初回ダウンロード・準備によって利用条件が変わります。本番の全端末でモデル動作を検証したわけではありません。

今回、個人情報を新しくGoogleの生成AIへ送信する経路は追加していません。既存のGoogle側の集計・文体設定機能と、個人の文章を端末内で整理する処理は別です。APIキーが登録されているだけで、候補者向けの文章生成がクラウドAIへ切り替わるとは説明しません。

新しい紹介文入力は旧基本情報を破壊的に上書きしません。検索・条件比較・候補者チャットは、明示した候補者ID・記録IDに結び付くV2入力を読み取り専用に変換して参照します。不明な項目へ古い値を補充しません。社内メモは企業版・社内共有本文に自動挿入せず、本人・管理者の端末内チャットでは別の参照資料として扱います。

社内への公開はプレビューと明示した共有操作を通します。保存しただけで私有の候補者情報が全員に公開されるわけではありません。過去のSlack投稿を実際に一括移行する作業、およびモデルの重みの学習は今回実施していません。

## 保存・合意資料・書き出し

- 新機能の保存は、既存の暗号化された端末内の保存待ち処理と、サーバーの操作ID・確定応答へ接続しています。応答を失った入力は、同じ内容と同じ操作IDで結果を確認します。
- Firestoreの背景同期は、同じセッションで取得した全データに限り、変更がない間は名簿・権限と更新位置を確認します。初回・手動更新・権限や設定の変更時、および最長5分ごとには全データを取得します。候補者の私有データを端末の表示キャッシュへ追加する仕組みではありません。
- 長いV2原稿用の保存待ち上限だけを拡張し、その他の操作の上限は維持しています。暗号方式、本人の秘密情報による復号、ログアウト時の鍵の破棄、保存期限は変更していません。
- 合意画像はPNG・JPEG・WebP、5MB以内の非公開資料として扱います。候補者側とクライアント側を分け、提出時にも所有関係・形式・容量・変更不能な世代番号を確認するコードがあります。
- 一時アップロードURLはメモリー内だけで利用し、保存台帳・ログ・バックアップへ含めません。実際の本番バケット・IAM・OAuth認可・アップロードは別途確認が必要です。
- 管理者向けの書き出しは、過去月の目標、案件、提案予定・送付済み履歴、報告の下書き、紹介文の原稿・社内メモ・設定を保持します。全員向けの共有データではありません。画像本体やアップロードURL、GCSの保存場所、認証秘密情報は含めません。

## 検証と本番への残作業

紹介文、入力変換、候補者との関連、閲覧権限、目標、提案の二重計上、報告・合意資料、保存待ちの暗号化・復元・同一操作での再確認、書き出しの合成テストを追加しています。既存のチャット・セッション・保存待ちテストも関連変更時に実行しています。

`tests/firestore-workflows.test.mjs` は実Firestore EmulatorのREST境界を通して各機能を確認するためのテストです。画像のGCS側はモックです。Emulatorの成功を、本番の課金設定・IAM・リージョン・Storage・Google認可・実データ移行の成功と混同しません。通常テストは1,479件成功・Emulator専用4件を除外。Emulator接続を指定した3ファイルを直列実行して43件成功。画像のGCSは模擬応答であり、本番公開・実データ切替の確認とは分けて記録します。

```sh
npm test

npm run security:artifacts
```

Emulatorを起動した場合は、対応するローカルの接続先を指定し、`--test-concurrency=1` で専用テストを直列実行します。同じcollectionIdへの並行したRW範囲検索でEmulatorのロック制約に当たるためです。本番のScriptLockによる書き込み直列化は維持します。実プロジェクトや元データをテスト用に変更しません。

```sh
NODE_FIRESTORE_EMULATOR_URL=http://127.0.0.1:8080 node --experimental-strip-types --test --test-concurrency=1 tests/firestore-emulator.test.mjs tests/firestore-workflows.test.mjs tests/firestore-streaming-migration.test.mjs
```

1. Google側の課金・追加OAuth認可・IAM、および非公開画像保管の本番設定を完了する。
2. 公開済みの互換サーバー版で、切替開始時に保存受付が停止することを確認する。
3. 元データを変更せず取り込み、全表・全行・管理ID・操作履歴を照合してから明示的に保存先を切り替える。
4. 本番の担当者・管理者で登録、修正、再読込、権限、画像、書き出しを確認し、PC・スマホで代表導線を確認する。
